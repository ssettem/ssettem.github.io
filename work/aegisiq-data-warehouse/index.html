AegisIQ Data Warehouse Design

GRADUATE COURSEWORK · STAR SCHEMA MODELING
AegisIQ · Graduate Coursework, Lewis University

AegisIQ is a course case: a Dota 2 coaching-analytics business with 150 staff across four sites, each tracking player performance, coaching sessions, revenue and staffing in its own way, so the numbers never agreed. I designed one shared reporting database: requirements first, then an ER diagram of the tables, keys and relationships, then a star schema and the data mapping behind it.

What I actually built

01

Starting from the questions, not the tables

Before drawing a single table, I mapped what each of the four sites actually needed to report on. A warehouse schema is only as good as the requirements it was built against.

02

One centralized structure, not four one-offs

I designed a single warehouse structure every site could report against, instead of letting each site's reporting needs harden into its own incompatible schema.

03

Documentation the next review didn't have to redo

I wrote supporting documentation detailed enough that later requirements reviews could build on it instead of re-litigating it, including the source-to-target data mapping.
